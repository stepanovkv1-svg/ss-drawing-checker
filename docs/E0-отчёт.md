# Этап 0. Отчёт об испытаниях разбора PDF

Дата: 03.11.2026. Материалы: три PDF проекта из AutoCAD 2024 с текстовым слоем:
- НСС-02, 7 листов (A3x4, A1, A2x3, A3);
- оптические схемы, 5 листов, два из них с поворотом 270°;
- НСС-03, лист 3 (A2x3).

Испытания проведены в среде разработки (Linux, 4 ядра). Сборку для Windows проверяет GitHub Actions (`windows-2022`): собранный exe прошёл самопроверку, то есть открыл PDF, распознал повёрнутый лист, нашёл надпись и распознал её через встроенный Tesseract. Итоговая проверка — запуск у Кирилла на Windows 11.

## Итог

**Стек подходит, менять ничего не нужно.** Два уточнения к ТЗ:
1. Основной движок для текста и координат — **pypdfium2**. pdfplumber оставить только для разбора таблиц по запросу: на тяжёлых листах он в 100–1000 раз медленнее, и на повёрнутых листах его координаты расходятся с отрисовкой.
2. OCR целых листов даёт 56–77% слов. Это ожидаемо для чертежей. Для сканов действует правило ТЗ: неуверенное распознавание идёт в «ручную проверку» и замечаний не создаёт. Надпись, которую OCR распознаёт по найденному месту, читается уверенно (73–96%).

## Что уже видно на ваших файлах

Это не замечания, а примеры того, что найдут базовые проверки Э1:
- даты в штампах: НСС-02 «10.26», оптические схемы и НСС-03 «10.2026» (БП «разный формат дат»);
- в оптических схемах листы «МТС» и «Ростелеком» оба помечены как лист 1 (БП «дубль номера листа»; нужно подтверждение инженера, возможно, это разные документы).

## Компоненты (для справки)

PySide6/Qt (LGPL), pypdfium2/PDFium (Apache-2.0/BSD), Pillow (MIT-CMU), Tesseract (Apache-2.0). Полный список кладётся в сборку автоматически (`THIRD-PARTY-NOTICES.txt`). PyMuPDF не используется. Размер сборки около 350 МБ (архив около 150 МБ), большую часть занимают Qt и Tesseract.
